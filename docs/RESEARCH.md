# BUGFIRE 玩法与可定制系统调研

> 调研日期：2026-07-16。只记录能由官方站点、官方文档或项目仓库直接确认的公开机制；第三方素材不进入本仓库。

## 结论

BUGFIRE 最适合发展的不是“更多固定皮肤”，而是一个本地、可分享、可验证的桌宠包协议：用户提供背景和宠物素材，系统负责六状态反馈、模拟 Build、XP、成长卡、任务板、台词、主题库、导入导出和恢复。它保留桌宠的陪伴感、游戏化的即时反馈与主题工具的可逆性，同时不采集源码和任务正文。

## 新增玩法

### 已实现

- `Bugfire Pack v1`：背景、六状态宠物图、颜色、名称、台词、任务和纪念卡标题的统一协议。
- 最小两图模式：背景 + idle 宠物；缺失状态自动复用 idle 图。
- 完整六状态模式：`idle`、`building`、`bug`、`fire`、`success`、`levelUp`。
- 点击互动：宠物从包内台词池随机回应。
- 本地任务板：从 XP、等级、失败/成功/修复聚合数派生，不增加新的监控数据。
- 可移植编译包：带 `theme.json`、本地素材和 `pack-report.json`，支持主题库切换。
- 离线预览页和可安装 Skill；安装前做路径、格式、大小、字段、版权声明与 payload 校验。

### 推荐后续版本

- 多宠物同屏与“伙伴编队”，建立独立存档迁移规则后再做。
- 纯本地专注计时器，必须独立开关且不把时间等同生产力。
- 社区 pack 索引，需要签名、许可字段、内容审核与撤下机制。
- 真实 Build 适配器，只有在用户逐项目显式配置命令白名单后才可开发；只消费退出码。

## 产品边界

任务板与等级是本地娱乐反馈，不是客观技能评估或专业资格。定制包不包含可执行代码、远程 URL、SVG、GIF、symlink 或超出目录的路径。公开分享时不得包含进度、日志、个人路径、任务截图、认证信息或 API 配置。
