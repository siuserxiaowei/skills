# Lark Calendar｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “约张三和李四下周二 15:00 开 45 分钟会，优先 A 会议室。”
- **处理：** 解析自然语言为带时区时间，消歧参会人，查询忙闲和会议室冲突，展示标题、时间、人员、会议室与提醒预览后再创建。
- **验收证据：** 事件 ID 回读；开始/结束时间、时区、参会人和会议室一致；邀请确已发送且冲突状态明确。

## 边界案例

- **场景：** 取消既有日程或向外部参会人发邀请需要针对具体事件确认，不能从查询忙闲自动升级。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 首选会议室冲突时列出可选空闲资源，等待用户选择；不静默换地点后发送邀请。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
