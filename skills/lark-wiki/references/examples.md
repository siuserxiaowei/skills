# Lark Wiki｜验收案例

Wiki node token 用于树操作，底层 obj token 用于内容编辑；两个 token 不得互换。

## 使用说明

- **何时使用：** 浏览、创建、复制、移动或管理 Wiki 空间、节点和成员。
- **准备/输入：** space/source/target/member、动作、当前树/权限基线、profile/identity 及异步停止条件。
- **执行方式：** 先解析 node 与 obj token、parent/子树和继承权限，展示目标路径或成员 diff，执行后按 node/task ID 回读。
- **验收/边界：** 同一节点、父子树和角色状态可证明；跨空间、移出、权限、删除分别需要独立授权，不用改权限绕过失败。

## 正向案例

### 移动已确认的节点

- **用户请求：** “把知识空间里的‘八月复盘’移动到‘项目归档/2026’下面，不复制。”
- **准备信息/输入：** 用户给出源节点和目标父节点链接；两个对象可唯一解析；用户授权移动及其权限继承影响。
- **处理：** 运行 `lark-cli wiki --help`、`lark-cli wiki +node-get --help`、`lark-cli wiki +node-list --help`、`lark-cli wiki +move --help`；读取 source/target 的 space_id、node_token、obj_type、obj_token、parent 与面包屑；列出源子树和目标权限继承；展示新路径后单次移动；按同一 node token 回读 parent、breadcrumb 和子节点。
- **预期输出：** 原节点被移动而非复制，同一 node token 出现在新父级下，子树完整。
- **验收证据：** 写前/写后 parent 与 breadcrumb、node token、子树计数、旧父级/新父级列表和权限影响摘要。

## 边界案例

### 移动同时要求删除旧节点和改成员

- **用户请求：** “跨空间搬过去，旧的删掉，再把全员改成管理员。”
- **边界判断：** 跨空间、删除和成员角色变化是三个高影响动作；恢复语义可能不同。
- **处理：** 分别核对 move/copy/move-to-drive/delete 的实际语义、目标空间权限和成员 diff；不把移动授权扩展为删除或权限提升。每个动作都需精确对象、影响预览和单独确认。
- **预期输出：** 在确认前树结构与成员不变；不会把快捷方式当成内容副本。
- **验收证据：** 三份独立计划、子树/成员基线和零高风险写入日志。

## 失败与恢复

### 移动响应未知或目标父级非法

- **场景：** 请求超时，或服务端提示权限不足/循环父级。
- **处理与恢复：** 不尝试随机父节点，也不改权限绕过；先对同一 node token 执行 node-get，并分别检查旧/新父级列表。若已移动则回读子树；若未移动则保持原状；无法确定时报告未知并等待证据。
- **预期输出：** 不产生重复节点或循环，不重放未知移动。
- **验收证据：** 原错误、source node 当前 parent、两侧列表、异步 task 状态（若有）与明确恢复条件。
