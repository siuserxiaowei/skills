# Lark Drive｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “把这份已确认的文件移动到项目归档文件夹。”
- **处理：** 先把来源与目标解析为 canonical token，读取名称、类型、当前父级和目标权限；预览移动影响后执行并回读新父级。
- **验收证据：** 同一 file token 出现在目标父级，源位置不再重复；继承权限变化已记录，下载内容未被改写。

## 边界案例

- **场景：** 删除文件、改共享权限或跨空间复制分别需要精确授权与恢复路径，不能与移动混在一次模糊请求里。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 权限不足或同名冲突时不创建重复副本；报告实际状态和可选命名/权限方案。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
