# Lark Skill Maker｜验收案例

案例强调从当前运行时事实独立设计 Skill；旧 Skill 只能帮助盘点覆盖面，不能作为文字模板。

## 使用说明

- **何时使用：** 把一个窄 Lark API 操作或多步 CLI 流程沉淀为原创、可验证的 Skill。
- **准备/输入：** 业务结果、正反触发案例、目标目录、当前 CLI/help/schema、官方来源和测试授权边界。
- **执行方式：** 建立事实表和风险闭环，只为重复的确定性逻辑增加脚本，并运行结构、无凭证和失败路径测试。
- **验收/边界：** 描述不吸走相邻请求，命令有来源，未验证写路径明确标注；不复制旧指南、不自动登录/升级/扩权。

## 正向案例

### 沉淀一个窄范围只读 Skill

- **用户请求：** “为‘按日期汇总我参加的会议’做一个可复用 lark Skill。”
- **准备信息/输入：** 用户给出期望输出、相邻能力和目标安装目录；本机存在可检查的 `lark-cli`，但真实远端测试不是默认授权。
- **处理：** 用 `lark-cli --version`、`lark-cli skills list`、相关 domain `--help` 与 `lark-cli schema --help` 定位当前能力；写出正向请求和不应触发的反例；记录 identity、scope、risk、时间/分页语义与官方 `doc_url`；设计只读工作流、失败降级和验收证据；运行结构校验、无凭证测试和静态安全检查。
- **预期输出：** 一个只承担明确业务结果、说明运行时发现和版本边界的原创 Skill，不复制内置指南长文。
- **验收证据：** `SKILL.md`、按需 references、来源记录、测试输出、quick_validate 结果及“真实远端未测试”的明确标记。

## 边界案例

### 要求制作万能飞书 Skill

- **用户请求：** “把所有飞书操作都写进一个 Skill，顺便自动申请全权限。”
- **边界判断：** 请求跨多个互不相同的业务域并涉及权限扩张。
- **处理：** 拒绝让一个描述吸走全部 Lark 请求；按可验收业务结果拆分或路由到现有 Skill。权限只记录每个流程的最小 scope，脚本不得自动登录、升级 CLI、申请 all scope、发送或删除。
- **预期输出：** 得到边界清楚的拆分建议或单一 Skill，不产生授权变化。
- **验收证据：** 触发/不触发示例、相邻 Skill 路由表、每条命令的 scope/risk 与无外部写入测试日志。

## 失败与恢复

### 文档与本机命令不一致

- **场景：** 官方页面描述某 flag，但当前二进制 `--help` 中不存在。
- **处理与恢复：** 以当前二进制作为可执行事实，记录页面 URL 与版本差异；不把未知 flag 写进案例。若能力确实要求更高版本，声明最低已验证版本或提供受证据支持的降级路线，不能自动升级。
- **预期输出：** Skill 不会在当前环境承诺不可执行命令，未验证写路径保持待验证状态。
- **验收证据：** CLI 版本、help/schema 摘要、差异记录、被省略/降级的命令及测试覆盖的失败分支。
