# Lark Skill Maker｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “为当前 lark-cli 的一个新资源生成窄触发 Skill。”
- **处理：** 先读取运行中 CLI 的 version、skills list、help 与 schema，从真实能力提取触发、读写边界、身份、风险门禁和回读方法，再生成最小包。
- **验收证据：** 新 Skill 通过结构验证；示例命令与当前 CLI help/schema 一致；没有复制静态大手册、凭证或用户路径。

## 边界案例

- **场景：** 若命令/字段只存在于旧文档而当前 CLI 不认识，就标注版本条件或不生成，不能伪造支持。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 生成后探测失败时回到运行时发现修正路由和参数，并补失败案例；不靠放宽验证器让错误 Skill 通过。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
