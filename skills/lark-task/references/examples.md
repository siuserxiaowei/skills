# Lark Tasks｜验收案例

示例中的人员、task/list/section ID、deadline flag 与回读命令必须来自当前对象和 `lark-cli task ... --help`。

## 使用说明

- **何时使用：** 查询、创建、分配、更新、完成/重开或组织飞书任务及其协作对象。
- **准备/输入：** task 或查重条件、唯一人员/清单、deadline 与 IANA 时区、profile/identity 和通知授权。
- **执行方式：** 先查询消歧和查重，展示负责人/截止/通知预览，单次写入后按 task ID 回读全部关键字段。
- **验收/边界：** 不误建、不误分配、不重复通知；完成、删除、批量改人或外部评论必须按准确任务单独确认。

## 正向案例

### 创建带清单的时区任务

- **用户请求：** “给王明创建一个本周五 18:00 截止的任务，放到‘交付’清单，带三项子任务。”
- **准备信息/输入：** 用户指定 IANA 时区；王明和目标清单能够唯一解析；用户授权创建及由此产生的通知。
- **处理：** 运行 `lark-cli task --help`、`lark-cli task +create --help`、`lark-cli task +get-my-tasks --help`；用当前查询能力按标题、负责人、清单和时间窗查重；把周五落为绝对日期、18:00 和偏移；展示负责人、deadline、清单、三项子任务与通知影响；单次创建并按返回 task ID 回读。
- **预期输出：** 只创建一个任务，负责人、截止时区、清单和子任务完全匹配。
- **验收证据：** 查重范围与分页、创建响应的 task ID、回读的 title/status/assignee/deadline/list/subtasks，以及没有额外关注者或附件。

## 边界案例

### 同名人员与日期缺少时区

- **用户请求：** “给王明建个周五到期的任务。”
- **边界判断：** 搜索出现两个王明；用户未给时区和具体时刻。
- **处理：** 停在预览阶段，展示最小可辨认候选并询问准确成员；把 date-only 与具体时间分开，不按本机时区擅自补 18:00；不因候选顺序选择第一人。
- **预期输出：** 信息不足时不创建，也不通知任何人。
- **验收证据：** 消歧候选、缺失字段列表、零写入/零通知记录。

## 失败与恢复

### 创建请求超时

- **场景：** 创建已提交但响应丢失。
- **处理与恢复：** 不立即重试；按预览中的标题、负责人、清单、deadline 和时间窗完整分页查询。唯一匹配则回读并认领为已创建；无匹配且能证明远端未写入时才重新计划；多匹配则报告冲突，不能自动删除。
- **预期输出：** 避免重复任务，未知状态保持可见。
- **验收证据：** 原 operation/幂等键、提交时间、查重条件与分页、匹配 task ID、最终状态或下一步人工选择。
