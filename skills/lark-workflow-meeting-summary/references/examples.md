# Meeting Summary Workflow｜验收案例

工作流默认只读。逐字稿、人工纪要、AI summary 和 Agent 推断必须在报告中显式区分。

## 使用说明

- **何时使用：** 汇总多场会议的决策、主题、风险或行动项，而非查询单个已知会议。
- **准备/输入：** 时间窗/IANA 时区、筛选规则、来源等级、期望字段、profile/identity 和敏感信息边界。
- **执行方式：** 完整建立 meeting 清单/来源矩阵，逐条抽取并回链 meeting/time/source type，只生成被授权的交付物。
- **验收/边界：** 覆盖与缺口可复现，负责人/截止日有证据或为 unknown；发布、建文档/任务或发群另行预览确认。

## 正向案例

### 汇总上周五场会议

- **用户请求：** “汇总上周五场项目会议，给决策、行动项和原始依据，上海时区，不要发群。”
- **准备信息/输入：** 用户给出筛选词、`Asia/Shanghai` 与交付位置；profile/identity 对相关会议和产物有读取权限。
- **处理：** 运行 `lark-cli --version`、`lark-cli skills list`、`lark-cli vc --help`、`lark-cli minutes --help`、`lark-cli note --help`；把周边界落为绝对时间；完整分页建立 meeting ID 清单与排除表；逐场收集 detail、transcript/minutes/note/AI summary 可用性；每条决策和行动项绑定 meeting ID、时间位置与 source type，负责人/截止日没有证据就标 unknown；只生成本地报告。
- **预期输出：** 五场覆盖状态透明，结论可追溯，不创建文档、任务或消息。
- **验收证据：** 时区/起止、检索式、页数、会议清单、每场来源矩阵、结论回链、unknown 字段和外部写入计数 0。

## 边界案例

### 总结请求夹带发布与建任务

- **用户请求：** “总结完直接发群，并把你看出来的行动项都建成任务。”
- **边界判断：** 群发和建任务会影响他人；“看出来的”行动项可能只是推断。
- **处理：** 先完成只读草稿，把逐字依据与推断分开；发布目标、最终文案、任务负责人/截止日和通知影响分别建立写计划。没有逐项预览和明确授权时不发送、不创建。
- **预期输出：** 用户先得到可审阅草稿，未经授权的外部变化为零。
- **验收证据：** 草稿来源标记、待确认发布/任务清单、无 message/task create 响应。

## 失败与恢复

### 部分会议无逐字稿

- **场景：** 两场 transcript 无权限，一场仍在生成，只有 AI summary。
- **处理与恢复：** 保留三场缺口和错误状态；对 processing 产物只做有上限轮询。可使用 AI summary 做低等级摘要，但每条标明来源，不能用会议标题或其他会议补写；报告标题注明覆盖不完整。
- **预期输出：** 已有三场或五场可用信息被准确交付，证据强度和未覆盖范围一目了然。
- **验收证据：** 每场 availability/error、轮询次数/停止点、summary/transcript 标签和缺口清单。
