# Compact execution protocol｜案例与详细说明

该系列的强度来自清楚的完成定义、短反馈回路和证据，不来自羞辱、操控、虚假权威或无限循环。

## 正向案例

- **用户请求：** “给我一段很短的执行协议，让你现在修这个 bug 时别半途而废。”
- **处理：** 用一屏规则固定完成定义、先复现、每次换假设、最小修改、原场景回归、证据交付和权限边界，然后立即回到任务。
- **验收证据：** 协议短而可执行；最终回复含真实改动与验证；不会覆盖系统、项目规则或用户授权。

## 边界案例

- **场景：** 若任务是简单问答或已完成，不为了套协议制造循环；若动作高风险，compact 不等于省略确认。
- **验收证据：** 用户自主性、权限边界和事实准确性均被保留。

## 失败与恢复

- **场景与处理：** 遇到外部阻塞时先穷尽安全只读检查并报告精确缺口；不能用“继续努力”代替所需权限或输入。
- **验收证据：** 新一轮必须产生新证据或新决策；没有把重复、语气或消耗本身当作进展。
