# macOS 微信双开｜案例与详细说明

以下案例把触发条件、处理决策和验收证据连在一起。示例中的账号、路径、对象和内容均为占位描述，执行时必须替换为用户已确认的真实范围。

## 正向案例

- **用户请求：** “给我做一个蓝色图标的 WeChat-2，原微信不能受影响。”
- **处理：** 先核对系统、原应用签名与目标路径；只复制到用户级 Applications，修改副本 bundle id、蓝色图标与语言偏好，再对副本临时签名并启动。
- **验收证据：** 原 `/Applications/WeChat.app` 哈希/签名未改；两个实例可并存；副本名称、图标、bundle id 和数据容器可区分。

## 边界案例

- **场景：** 若目标副本路径已存在，先只读检查并让用户决定复用、另命名或移到废纸篓；不覆盖，也不安装注入插件。
- **验收证据：** 未获授权的动作没有发生，结果明确标记适用范围与剩余选择。

## 失败与恢复

- **场景与处理：** 系统更新后副本打不开时，从当前正版应用重新生成新副本并保留旧副本作回退；不修改正版包来迁就旧副本。
- **验收证据：** 失败状态、已完成范围和下一次安全重试条件均可复核。
