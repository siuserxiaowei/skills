# Lark Mail｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “起草一封带报价单的客户邮件，确认后再发。”
- **处理：** 先核对发件身份、To/CC/BCC、主题、正文和本地附件路径，创建或展示草稿预览；用户确认精确版本后才发送并查 sent 状态。
- **验收证据：** message ID、收件人、主题和附件名称/大小回读一致；无密送泄露，草稿与发送版本可对账。

## 边界案例

- **场景：** 用户只说“写封邮件”时默认停在草稿；群发、外部域、敏感附件或回复全员都要额外核对。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 发送结果未知时先按草稿/消息 ID 查询，不重新发送；附件上传失败则保持草稿并报告缺失。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
