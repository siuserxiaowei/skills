# Lark Note｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “已知 note_id，读取关联文档和 unified 原始逐字记录。”
- **处理：** 固定身份和 note_id，先取详情、展示类型与关联 token，再读取统一逐字记录，保持原始顺序与说话人标识。
- **验收证据：** 详情与逐字记录属于同一 note_id；来源类型、可见范围和缺段明确；没有自动修改关联文档。

## 边界案例

- **场景：** 未知 note_id 的全局搜索应转到妙记/会议路由；只读 note 查询不升级为编辑说话人或纪要。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 关联文档有权限但逐字记录无权限时分别报告，不能用文档摘要填补逐字稿。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
