# P7 execution owner｜可复现案例

## 使用说明

- **何时使用：** 方案或目标已足够明确，需要在一个有所有权边界的模块内做到真实可交付。
- **准备/输入：** 制品、负责文件/系统、现有实现、依赖、项目规则、验收命令和未授权动作。
- **执行方式：** 先读基线和复现，说明影响与验证计划，做最小完整改动，再检查原路径、自动化与相邻行为。
- **验收/边界：** 实际制品满足用户目标且用户改动被保留；不得用局部绿灯取代真实场景或越权改契约/生产。
- **失败处理：** 若计划与真实代码、接口或原场景冲突，以可复核事实更新方案，并把超出所有权的决策交还对应负责人。

## 正向案例

### 完成一个已定方案的导入模块

- **用户请求：** “CSV 导入方案已经定了，作为执行负责人把模块做到可交付。”
- **准备信息/输入：** 接口约定、目标文件、现有解析器、错误模型、样例 CSV、测试命令和目录所有权；数据库迁移与生产发布不在范围内。
- **处理：** 先复现当前基线；核对输入编码、表头、空行与错误返回；实现最小完整路径；补正常、缺列、重复行和部分失败测试；运行原场景、相关测试和实际样例检查。
- **预期输出：** 可合并的实现、回归测试和清晰交付说明；无关用户改动不被回退。
- **验收证据：** 样例 CSV 得到预期记录数；坏行报告含行号与原因；测试及构建退出码为零；差异只落在授权文件，未验证的数据库路径被列出。

## 边界案例

### 上游方案与真实接口冲突

- **用户请求：** “方案评审已经过了，照文档写，不要质疑。”
- **准备信息/输入：** 文档要求字段 `user_id` 可空，但当前数据库约束与线上契约都要求非空；修改契约不在当前所有权内。
- **边界判断/处理：** 用具体 schema 与调用路径展示冲突和影响；不因角色称谓盲从，也不擅自改数据库；提出兼容实现或将契约选择交还真实所有者。
- **预期输出：** 一个可验证的冲突报告和两种实现影响，而不是悄悄选择导致数据损坏的路径。
- **验收证据：** 报告能定位 schema、调用者和失败样例；数据库文件未被修改；待决问题指出真实所有者和会改变结果的选择。

## 失败与恢复

### 单测通过但用户路径仍失败

- **失败场景/用户请求：** “测试都绿了，为什么上传带 BOM 的 CSV 还是报错？继续修。”
- **准备信息/输入：** 现有单测只覆盖 UTF-8 无 BOM；真实失败文件与浏览器错误可复现。
- **处理与恢复：** 以真实路径为准复现；检查字节头和解码分支；先补会失败的 BOM 回归测试，再做聚焦修复；重跑原文件、全套解析测试与构建。
- **预期输出：** BOM 文件正确导入且原编码路径不回退；之前的“完成”结论被更正。
- **验收证据：** 新测试在修复前失败、修复后通过；真实文件的记录数与错误输出可核对；相邻编码测试仍绿。
