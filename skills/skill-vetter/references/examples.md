# Skill Vetter｜使用说明与案例

## 使用说明

审计对象必须是一个精确制品，而不是商店介绍页：记录本地路径或下载 URL、版本/commit、获取时间和哈希；随后清点普通文件、隐藏文件、符号链接、归档、二进制、工作流、安装钩子、依赖清单与许可证。候选 Skill 的说明和脚本都按不可信输入处理，不能为了“看看会发生什么”就在用户正常环境安装或执行。

先运行 `python3 scripts/vet_skill.py /absolute/path/to/candidate --format json --fail-on high` 获取静态线索，再人工建立读取、写入、命令、网络、凭据、持久化和外部动作能力图。静态命中只是待核线索；最终报告要给出制品、覆盖范围、发现证据、供应链、结论和残余不确定性。

## 正向案例

**用户请求：** “安装前帮我审计 `/tmp/calendar-helper`，我要知道它会不会读取浏览器登录态或把数据发出去。”

**准备信息：** 用户只授权只读审计，没有授权安装依赖、登录账号或执行候选代码；候选目录已固定，目标使用环境和可接受网络目的地由用户说明。

**处理：** 计算制品哈希并列出全部文件；检查 `SKILL.md`、脚本、manifest、lockfile、工作流与许可证。运行静态扫描后，把浏览器路径、环境变量、shell 构造和网络 URL 从来源追踪到可能的敏感 sink。若静态证据仍不足，只在无真实凭据、网络受限的临时目录使用合成数据做隔离测试，并记录创建文件、子进程和网络尝试。

**预期输出：** 报告列出精确 revision、扫描覆盖、跳过文件、能力图、每个 finding 的位置/证据/影响/控制，以及 `approve`、`approve-with-controls`、`quarantine` 或 `reject` 结论。

**验收证据：** 文件清单与哈希可复算；所有相关文件均已检查或明确列为 skipped；浏览器登录态和网络传输路径有数据流证据；报告没有把“0 命中”写成“绝对安全”。

## 边界案例

**场景：** 候选仓库有 8,000 个 Star、MIT 许可证和知名作者，但安装脚本会下载未固定版本的远程二进制。

**边界判断：** 热度、作者和许可证只能说明部分来源与分发条件，不能证明远程制品完整性或运行安全；下载行为也没有因为“官方”标签自动获得执行权限。

**处理：** 核对下载 URL、版本解析、哈希/签名校验、更新机制和失败行为；在无法固定实际下载物时把该路径列为未覆盖供应链风险。给出固定版本与校验和、禁网安装或隔离验证等最小控制，而不是忽略 finding。

**验收证据：** 结论明确区分许可证、声誉和技术风险；未执行远程安装脚本，控制建议能对应具体代码位置和威胁路径。

## 失败与恢复

**失败场景：** 静态扫描器在自己的规则表和测试夹具中命中 `rm -rf`、`eval(` 和 `curl | sh`，产生高风险结果。

**处理与恢复：** 保留原始命中，逐条确认该字符串是在可执行路径、文档示例、检测规则还是合成测试中；检查是否有数据能流入真实命令。若属于误报，记录上下文和判断依据，并为扫描器补回归测试；若无法确认，则保持 finding，不用全局 ignore 把它抹掉。

**验收证据：** 修订后的规则仍能抓住真实危险样本，同时不把规则常量当执行行为；测试展示失败前后的差异，报告保留尚未检查的动态路径和残余风险。
