# Lark Meetings｜验收案例

本 Skill 以历史和进行中会议的只读发现为主。event、meeting、meeting number、minute/note token 不能互换。

## 使用说明

- **何时使用：** 搜索历史/进行中会议，读取详情、事件、参与人线索、录制或纪要关联。
- **准备/输入：** meeting ID 或可复现过滤器、绝对时间窗/IANA 时区、来源口径、profile/identity 与隐私范围。
- **执行方式：** 完整分页，以 meeting ID 去重，逐场读取并区分邀请、参与快照、事件、逐字稿和 AI 产物。
- **验收/边界：** 会议清单与来源可追溯，缺失产物不被补写；入会、发言和离会转 vc-agent 重新授权。

## 正向案例

### 汇总上周项目会议来源

- **用户请求：** “找出上周所有项目会议，列出实际参会线索和可用纪要来源，不要进会。”
- **准备信息/输入：** 用户给出“上周”所用 IANA 时区与项目筛选词；profile/identity 有合法读取权限。
- **处理：** 运行 `lark-cli vc --help`、`lark-cli vc +search --help`、`lark-cli vc +detail --help`；把周边界转为带偏移的绝对起止；按当前 help 支持的过滤器完整分页搜索，以 meeting ID 去重，再读取详情、服务端参与人快照、事件、录制和 minute/note 关联状态。
- **预期输出：** 返回完整会议清单；邀请名单、参与人快照、进出事件、逐字稿和 AI summary 分列标注来源。
- **验收证据：** 时区/起止、查询条件、页数/游标、meeting ID 数、每场 source type 与可用性，以及无 join/message/write 调用。

## 边界案例

### 同题会议和进行中会议

- **用户请求：** “把标题叫‘项目周会’的都合成一场，再帮我进去看看。”
- **边界判断：** 多个同题 meeting ID；其中一场仍 active；用户尚未指定机器人身份和入会影响。
- **处理：** 不按标题合并不同会议；先用时间、组织者和参与人消歧。历史读取可继续，但加入属于 `lark-vc-agent` 的外部实时动作，必须重新展示准确会议与 bot 身份并获得授权。
- **预期输出：** 历史证据保持逐场；本 Skill 不加入或发送内容。
- **验收证据：** 独立 meeting ID 列表、active 状态和转交说明；无参会者变化。

## 失败与恢复

### 某场纪要无权限或尚未生成

- **场景：** meeting 可读，但 transcript/minute 返回无权限、processing 或空结果。
- **处理与恢复：** 保留 meeting 条目和服务端状态；只在异步任务明确存在时按有限次数/间隔轮询，超时后标记未生成。无权限时报告 scope/成员关系缺口，不用其他会议摘要填补，也不把缺失解释为“未讨论”。
- **预期输出：** 能交付已证实的会议清单，同时清楚列出产物缺口。
- **验收证据：** 原错误码/状态、有限轮询次数、最终 source availability 和未覆盖清单。
