# Lark Markdown｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “把本地 README 的这一节同步到飞书 Markdown 文件。”
- **处理：** 读取本地与云端当前版本，规范路径与换行，生成可读 diff；在 revision 一致且用户授权后做局部更新并重新比较。
- **验收证据：** 云端目标段与本地一致；未触及其他段落；revision、时间和差异结果可追溯。

## 边界案例

- **场景：** 云端存在用户新改动时不自动以本地覆盖；整文件替换与冲突解决必须展示分支并让用户选择。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 更新后 diff 仍有非预期变化时停止后续动作，保留两份内容与 revision，按最小范围重做。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
