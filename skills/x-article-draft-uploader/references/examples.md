# 示例与验收证据

示例路径均为占位符，执行时只使用用户确认的真实文件和 profile。

## 正向案例

**用户请求：** 把首行是封面、正文有两张图片的 Markdown 保存为 X Article 草稿。

**处理：** 先预览 cookie 导出范围，再带 `--apply` 生成临时 storage state；随后预览文章计划，确认封面和两个正文锚点，最后带 `--apply` 创建草稿。

**验收证据：** 运行目录中存在草稿 URL、结果 JSON 与截图；标题及正文首尾验证为真；每张正文图都记录实际命中的锚点；`published` 为 `false`。

## 边界案例

**场景：** 文章开头是标题，用户明确表示无需封面。

**处理：** 在文章预览与草稿创建命令中都使用 `--no-cover`。原解析出的首图进入正文图片计划，不上传到封面槽。

**验收证据：** 预览的 `cover` 为 `null`，正文图片列表包含那张图，最终结果的 `cover_uploaded` 为 `false`。

## 失败与恢复

**场景：** 某张图片前没有可定位的文字，或编辑器内找不到任何候选段落。

**处理：** 停止当前运行，保留错误信息，不把图片随意插到文末。先在 Markdown 中补充稳定的相邻文字，再新建草稿重试。

**验收证据：** 失败运行没有被报告为成功；重试结果能给出该图片的候选锚点、实际可见段落和媒体计数增长。

### 登录态失效

现象：访问编辑器后跳回登录页面。

处理：关闭独立浏览器，重新选择正确 Chrome profile 并导出 storage state。不要打印或手工复制 cookie 值。

验收：新的导出文件权限为 `0600`，上传器能够到达新文章编辑页；任务结束后临时凭据按用户要求清理。
