# Goal Meta Skill｜使用说明与案例

## 使用说明

这个 Skill 只在用户明确希望建立长期、跨回合持续执行的 Goal 时使用。先把请求从“活动”改写成可验收结果，确认完整对象范围、约束、权限边界、外部状态、停止条件和证据；普通一次性任务、提醒或仅需一轮完成的工作不应创建 Goal。

起草后可运行：

```bash
python3 scripts/check_goal.py goal.json
```

检查通过只证明 Goal 合同字段和基本关系完整，不证明目标已经完成。执行过程中必须保留原始范围；只有所有要求都被权威证据覆盖才能标记 complete，同一真实阻塞连续达到产品规则阈值且无法继续推进时才可标记 blocked。

## 正向案例

**用户请求：** “把仓库里 57 个 Skill 的使用说明和案例都补好，后面几轮继续做，直到全部验证通过。”

**准备信息：** 已知仓库路径和 57 个对象清单；用户授权修改、测试和最终提交，但没有自动授权删除、公开发布、真实账号写入或缩小范围。完成标准需要同时覆盖使用说明、案例、链接、结构和行为验证。

**处理：** 把目标写成结果合同：57 个 Skill 全量覆盖；每个入口说明适用场景、输入、流程、边界、失败恢复和验收；每个案例包含正向、边界、失败恢复与可观察证据；建立逐项台账、自动检查、人工内容审计、全量测试和远端复验。明确中途抽样通过不算完成，单次 token/时间消耗也不是停止条件。

**预期输出：** Goal 文本保留完整范围和权限，列出可由文件、命令输出、测试结果和远端 SHA 验证的完成条件；后续回合能从当前工作树继续而不重新定义一个更小目标。

**验收证据：** `check_goal.py` 通过；57 项台账无缺口；Goal 能明确区分 progress、verified wait、no progress、complete 与 blocked；发布或删除仍需用户已有授权，未被 Goal 文字暗中扩张。

## 边界案例

**场景：** 用户说“今晚 9 点提醒我看看测试结果”，并不要求 Agent 跨回合持续完成代码工作。

**边界判断：** 这是一次定时提醒，应使用产品的自动化/提醒机制；创建长期 Goal 会错误扩大执行语义，也不会让提醒更可靠。

**处理：** 不调用 Goal 创建工具。解析用户时区、日期和提醒内容，用适合的调度能力建立一次性提醒；如果用户后来明确要求持续修复测试，再单独建立以“测试恢复并验证”为结果的 Goal。

**验收证据：** 只出现用户要求的提醒，没有后台代码修改或无限执行；提醒时间和时区可读回核对。

## 失败与恢复

**失败场景：** Goal 执行数轮后只完成 42/57 个 Skill，预算指标接近上限，执行者准备把目标改成“先完成 42 个”。

**处理与恢复：** 保留原始 57 项范围，记录已验证的 42 项和剩余 15 项，不把预算接近耗尽、一次测试失败或阶段性成果当 complete。继续执行仍安全的剩余工作；若遇到真实外部阻塞，先做只读替代检查和其他不依赖工作，只有同一阻塞连续达到产品规定阈值且已无可推进事项时才标记 blocked。

**验收证据：** Goal 状态仍反映完整目标，完成清单和缺口可核对；没有删除未完成项、伪造证据或仅因消耗停止。恢复后必须重新执行全范围完成审计，才能调用 complete。
