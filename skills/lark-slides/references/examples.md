# Lark Slides｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “给现有飞书幻灯片追加三页数据总结，并保持可编辑。”
- **处理：** 读取 deck 结构、主题和目标位置，建立三页内容/素材计划，确认写入后创建页面与元素，再做结构回读和真实渲染检查。
- **验收证据：** 页数、顺序、文本、图表数据和可编辑元素一致；截图中无溢出/遮挡；原页面未被重排。

## 边界案例

- **场景：** 像素级复刻外部模板或自动替换整个 deck 超出追加范围；只能借鉴一般属性并保持原创。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 结构 API 成功但渲染错位时以截图为准，修复对应元素后重查三页，不用 API 成功码冒充视觉验收。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
