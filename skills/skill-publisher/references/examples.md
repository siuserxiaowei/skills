# Skill Publisher｜案例与详细说明

以下案例把触发条件、处理决策和验收证据连在一起。示例中的账号、路径、对象和内容均为占位描述，执行时必须替换为用户已确认的真实范围。

## 正向案例

- **用户请求：** “检查这个 Skill 是否可以发布到一个新的私有 GitHub 仓库。”
- **处理：** 先只读解析 Skill、许可证、秘密、符号链接、Git 边界和目标仓库；输出哈希清单与发布计划。只有用户明确授权后才创建、提交、推送或发 Release。
- **验收证据：** 预检 blocker 为零；目标可见性、分支、提交集合和标签明确；隔离目录安装验证成功后才报告发布完成。

## 边界案例

- **场景：** 用户未选择许可证时不自动补 MIT；工作区有无关改动时不执行 `git add -A`，也不默认公开仓库。
- **验收证据：** 未获授权的动作没有发生，结果明确标记适用范围与剩余选择。

## 失败与恢复

- **场景与处理：** push 或 Release 失败就保留真实状态和可重试命令；不能跳过错误后继续宣布成功，更不能覆盖用户已有安装目录。
- **验收证据：** 失败状态、已完成范围和下一次安全重试条件均可复核。
