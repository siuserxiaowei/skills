# Xiaowei Aibeike Distribution 使用说明与案例

## 使用说明

**输入与准备：** 先确认视频路径、目标平台、账号、内容锚点、封面来源和期望结果。用户只说“同步”时，默认选择 package 模式；没有明确发布授权时，只生成并验证交接包，或把内容保存为草稿。平台字段、时长和封面限制以当前编辑器与官方资料为准，案例中的账号、路径和日期都是示意。

**流程与验收：** 锁定源文件 SHA-256，生成平台独立 metadata，运行创建器和验证器，再交给爱贝壳执行。每个平台必须单独回读标题、封面、视频预览、可见范围和草稿状态。上传动作、进度条或 API 返回本身不构成成功证据；成功必须有新鲜页面证据或可核验的官方回执。

**边界与恢复：** 缺少账号、登录态、版权声明、封面或平台规则时，标记 `blocked` 并保留当前包；超时先查询已有任务，再决定是否重试。最终公开发布始终是独立授权动作。

## 正向案例

**用户请求：** “把这个视频准备成抖音、小红书和 B 站的爱贝壳批量发布包，生成不同标题和标签，先不要发布。”

**准备信息：** 视频路径已确认；三个目标平台和账号已确认；用户提供核心观点、原始封面和不公开发布的要求。

**处理：** 锁定源文件 SHA-256；为三个平台生成独立标题、简介、标签和封面引用；运行 `create_delivery_package.py` 与 `validate_delivery_package.py`；把包交给爱贝壳保存草稿；逐个平台核对标题、封面、视频预览和草稿状态；用 `record_platform_receipt.py` 记录回执。

**预期输出：** 一个包含 `manifest.json`、三份 metadata、三份 status 和验证报告的发布包；每个平台都有稳定 job ID，后续只重试未完成的平台。

**验收证据：** `validation.json` 为 `valid: true`；三个平台各有新鲜草稿证据；回执包含平台、账号、草稿状态、时间和证据路径；manifest 仍保持 `publish.requested: false`。

## 边界案例

**场景：** 用户只提供视频，要求“全部平台都发”，但没有指定账号，也没有确认是否需要自定义封面或 AI 内容声明。

**边界判断：** 账号、封面策略和声明字段会改变实际发布结果，不能凭经验代选；当前只能准备素材和平台字段，不能保存草稿，更不能发布。

**处理：** 生成 package 模式的预检清单，把账号选择、封面策略、平台集合和声明字段列为待确认项；不打开发布页面，不猜测默认账号，不把一个封面强行套到所有平台。

**验收证据：** 输出 `prepared` 或 `blocked`，明确缺口和下一步输入；没有产生草稿、预约或公开发布回执；源文件指纹仍可复核。

## 失败与恢复

**失败场景：** 爱贝壳显示某个平台上传超时，但任务列表和目标平台都没有明确显示成功或失败。

**处理与恢复：** 保留原 campaign ID 和 job ID；先回到爱贝壳任务/草稿列表检查是否已有结果；有可验证草稿就记录 `drafted`，没有结果就记录 `blocked`；只重试该平台，不重新上传其他已验证平台。若平台出现新草稿，先核对标题、封面和账号，再更新回执。

**验收证据：** 页面状态与 receipt 一致；没有产生重复草稿；失败平台、查询时间、重试原因和下一步条件可追溯；未知结果没有被伪装成 `published`。
