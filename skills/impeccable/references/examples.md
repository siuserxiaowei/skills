# Impeccable｜可复现案例

## 使用说明

- **何时使用：** 需要设计、审计、实现或精修浏览器界面，并要兼顾真实内容、交互、响应式、无障碍和性能证据。
- **准备/输入：** 请求动作、项目规则/命令、真实内容与状态、设计系统、目标视口/输入方式、素材权利和编辑授权。
- **执行方式：** 先固定 surface contract，再从结构、层级、系统、行为、适配和视觉性格逐层决策；实现后做静态、渲染与交互验证。
- **验收/边界：** 原用户路径及宽窄视口可复核，键盘/名称/状态与素材 provenance 清楚；只审计不授权修改，截图或静态零发现不能单独证明完成。

## 正向案例

### 修复结账页的移动端与可访问性问题

- **用户请求：** “审计并修复这个结账页：手机会横向滚动，优惠码弹窗键盘不好用。”
- **准备信息/输入：** 项目规则、目标路由、启动/测试命令、真实结账文案与状态、现有 tokens/components、375×812 与 1440×900 视口、编辑授权；页面图片和图标的来源/使用权已知。
- **处理：** 先复现窄屏溢出和完整键盘路径；运行静态审计作为线索；定义需保留的支付行为与 analytics；聚焦修复容器尺寸、弹窗语义、初始焦点、循环与关闭后的焦点恢复；复测加载、错误、空优惠码、放大文字和 reduced motion。
- **预期输出：** 保留品牌与业务契约的聚焦代码改动、回归测试和两视口验证记录；不重写无关设计系统。
- **验收证据：** 375px 与 1440px 无非预期横向溢出；Tab/Shift+Tab/Escape 路径、可访问名称、错误关联和关闭后焦点均实测；测试/构建退出码、截图与变更文件可定位；素材 provenance 未被破坏。

## 边界案例

### 只授权审计，不授权修改

- **用户请求：** “只审计这个仪表盘，按严重度告诉我问题，先不要改代码。”
- **准备信息/输入：** 可读仓库和可运行页面；没有写入授权；用户提供了目标浏览器与主要角色。
- **边界判断/处理：** 只读取代码、运行只读静态检查并观察页面；将偏好与可用性缺陷分开；为每条发现提供证据、影响范围、置信度和复现步骤，不应用自动修复或格式化。
- **预期输出：** 一份有优先级的审计报告和建议验证步骤，工作树保持原样。
- **验收证据：** 审计前后 `git diff` 无新增修改；每条高风险发现能在文件行或浏览器路径复现；没有把品牌审美选择宣称为普遍规则。

## 失败与恢复

### 静态检查为零但弹窗困住焦点

- **失败场景/用户请求：** “审计脚本 0 finding，可真实使用时 Tab 出不去，也关不掉，继续修。”
- **准备信息/输入：** 浏览器复现录像/步骤、弹窗组件、零 finding 报告和代码修改授权。
- **处理与恢复：** 明确静态结果不能证明交互；用键盘逐步记录焦点序列；修复对话框命名、Escape、焦点循环和恢复；加入组件级回归；重新运行静态检查、真实键盘流程和窄屏检查。
- **预期输出：** 可退出、可恢复焦点且无背景误操作的弹窗；交付更正先前的“无问题”结论。
- **验收证据：** 自动化回归在旧实现失败、新实现通过；实测焦点顺序和 Escape 结果记录；关闭后焦点回到触发按钮；零静态发现不再被单独用作完成证据。
