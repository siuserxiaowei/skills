# Impeccable｜案例与详细说明

以下案例把触发条件、处理决策和验收证据连在一起。示例中的账号、路径、对象和内容均为占位描述，执行时必须替换为用户已确认的真实范围。

## 正向案例

- **用户请求：** “审计并修复这个结账页的可访问性和移动端问题。”
- **处理：** 先读取项目规则和真实页面，区分静态线索、渲染、交互与性能证据；得到修改授权后做聚焦修复，不重写无关设计系统。
- **验收证据：** 键盘路径、名称/标签、焦点、错误状态和窄屏布局均实测；相关测试通过，浏览器截图或检查记录能定位修复结果。

## 边界案例

- **场景：** 如果用户只说‘审计’，只报告证据与优先级，不改代码；品牌偏好也不能伪装成普遍可用性规则。
- **验收证据：** 未获授权的动作没有发生，结果明确标记适用范围与剩余选择。

## 失败与恢复

- **场景与处理：** 静态审计通过但真实弹窗困住焦点时，以浏览器行为为准，修复焦点管理并补回归测试；不得用静态 0 finding 宣称完成。
- **验收证据：** 失败状态、已完成范围和下一次安全重试条件均可复核。
