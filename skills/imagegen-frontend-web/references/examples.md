# Imagegen Frontend Web｜可复现案例

## 使用说明

- **何时使用：** 需要网站视觉概念、响应式参考集或可交付生产图片，而非仅写前端代码或做纯文字审计。
- **准备/输入：** 页面目标、真实内容、品牌 anchors、目标视口/尺寸、文字策略、素材来源/权利、输出与实现范围。
- **执行方式：** 写六维可见 brief，先生成一张诊断图，再按批准方向补必要视口；逐图检查并以 blueprint/manifest 交接。
- **验收/边界：** 尺寸、裁切、焦点、文案、alt、provenance/rights 和实现说明可查；概念图不能单独证明响应式、无障碍或生产性能。

## 正向案例

### SaaS 首页响应式 Hero 参考包

- **用户请求：** “为我们的仓储 SaaS 首页生成桌面和手机端一致的原创 Hero 视觉，并交给前端实现。标题要用真实 HTML。”
- **准备信息/输入：** 已授权的品牌色与产品照片、最终标题和 CTA、1440×900 与 390×844 目标视口、输出目录、前端技术栈、图片使用权说明；Logo 不进入生成图。
- **处理：** 写出主体、环境、视觉语言、光线、镜头、排版六维 brief；规定 live-overlay 安全区和焦点坐标；先生成一张桌面诊断图并检查产品几何、无文字/水印与品牌锚点；方向通过后制作独立手机裁切；为两张图写用途、alt 意图、权利与实现说明，生成 manifest 并运行严格校验；若实现也在范围内，再检查真实页面。
- **预期输出：** 桌面与手机两张最小必要参考图、实现 blueprint 和通过校验的引用包；标题/按钮保持语义 HTML，不栅格化进图片。
- **验收证据：** 图像头与尺寸匹配 1440×900、390×844；主体在两个视口均未被文字覆盖；文件 SHA-256、焦点、text strategy、alt、provenance/rights 齐全；manifest 严格校验通过；实现范围内的页面在两视口无溢出且键盘焦点可见。

## 边界案例

### 要求一比一复制无权使用的竞品图

- **用户请求：** “把这个竞品首页截图一比一做出来，Logo 也保留，我没有源文件。”
- **准备信息/输入：** 只有公开截图；用户未证明拥有截图、Logo 或独特插画的改编权。
- **边界判断/处理：** 不把截图当可复制资产或交付物；只提取高层属性，如高留白、右侧产品焦点、冷灰背景与单一暖色动作；为用户自己的内容重新构图、重画视觉语言并去除竞品标识；若用户坚持原样，暂停生成。
- **预期输出：** 原创方向说明或待授权状态，而不是竞品身份的复制品。
- **验收证据：** 交付包不包含原截图、竞品 Logo、原文案或可识别的独特构图；provenance 记录仅将其作为未打包的分析参考；剩余权利问题显式列出。

## 失败与恢复

### 桌面标语拼错且手机裁掉产品

- **失败场景/用户请求：** “第一稿方向对了，但标语错了，手机端只剩产品一半；别把已确认的风格重做。”
- **准备信息/输入：** 已批准的桌面色彩、光线和主体；拼错的栅格文字；手机焦点和安全区检查失败。
- **处理与恢复：** 保留已确认视觉；删除图内标语并改为 live-overlay；以同一主体和材质单独制作手机 art-direction crop；逐字核对 HTML 文案，重新测两个裁切与文字对比；更新 manifest 后再次严格校验。
- **预期输出：** 视觉方向不漂移、文案准确、两个视口主体完整的新版本，旧失败稿不被标记为生产资产。
- **验收证据：** 新旧差异仅涉及文字策略与手机裁切；真实 DOM 包含准确标题；两张图片的焦点/安全区检查通过；manifest 哈希随新文件更新且校验为零错误。
