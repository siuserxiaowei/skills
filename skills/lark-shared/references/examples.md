# Lark Shared｜验收案例

这些案例验证共同合同，不替代具体业务 Skill。所有身份敏感命令都在当前 help 支持的前提下显式携带同一个 `--profile` 和 `--as`。

## 使用说明

- **何时使用：** 配置/诊断 lark-cli，或任何 Lark 业务流程需要共同的身份、权限、时间、分页和写入控制。
- **准备/输入：** profile、user/bot identity、租户、目标对象、期望后置状态、IANA 时区与覆盖上限。
- **执行方式：** 从当前 help/schema 取得命令事实；复杂动作先校验 operation plan，再按“定位—基线—预览—授权—单次执行—回读”闭环。
- **验收/边界：** 退出码、顶层 `ok` 和业务回读一致；不泄露凭证、不切换默认身份、不把第一页当全集、不盲重试未知写入。

## 正向案例

### 只读检查身份与最小权限

- **用户请求：** “检查我现在的 lark-cli 登录身份和完成日历读取所需的最小 scope，先别改任何东西。”
- **准备信息/输入：** 用户指定 profile 名称与期望业务域；不授权登录、切换默认 profile、升级 CLI 或新增 scope。
- **处理：** 运行 `lark-cli --version`、`lark-cli skills list`、`lark-cli calendar --help` 与 `lark-cli whoami --profile NAME`；对候选资源读取当前 schema，比较实际 identity、tenant、已有 scope 与所需 scope。只报告最小缺口，不读取配置文件或 token。
- **预期输出：** 明确当前版本、profile、user/bot identity、tenant、可见能力与最小权限差距，远端状态不变。
- **验收证据：** 命令退出码、顶层 `ok`、脱敏后的 identity/tenant、schema 风险字段和“未执行认证/写入”的操作清单。

## 边界案例

### 空结果被误判为资源不存在

- **用户请求：** “bot 查不到表格，直接切成我的个人账号并申请全部权限。”
- **边界判断：** 当前查询为空；尚未证明 profile、tenant、identity、成员关系、分页或过滤器正确。
- **处理：** 保持原 profile，逐项核对 whoami、显式 `--as bot`、租户、资源可见范围、过滤器与分页；把切换身份和扩 scope 视为独立授权动作，不因空结果自动执行。
- **预期输出：** 给出空结果的已排除原因和最小下一步，不产生身份或权限变化。
- **验收证据：** 查询条件、分页游标、实际 identity 与每项排查结论；没有 `profile use`、重新登录或全量 scope 请求。

## 失败与恢复

### 写请求超时且结果未知

- **场景：** 创建命令在提交后网络断开，没有可靠成功响应。
- **处理与恢复：** 保留 operation/幂等键、目标摘要和提交时间；不重放创建命令。使用独立读命令按 canonical ID 或查重键查询远端，区分已创建、未创建和仍未知；只有证据证明未执行且用户授权仍有效时才重新计划。
- **预期输出：** 不产生重复对象；未知状态不会被包装成成功或失败。
- **验收证据：** 原命令退出码/stderr、查重查询范围与分页、远端对象 ID/状态或明确的“仍未知”，以及下一次安全动作条件。
