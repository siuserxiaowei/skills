# 变更、失败与验证

## 风险不是动词猜测

以目标命令 help/schema 的 `risk` 为准。相似动作可能风险不同；更新标题、转移所有权、覆盖内容和删除历史版本不能共用一条默认策略。

## 确认门禁

当 CLI 以 exit 10 和 `confirmation_required` 拒绝时：

1. 保留原始 argv 与 dry-run 结果；
2. 向用户展示对象、影响、不可逆性和关键差异；
3. 只有用户同意这一次精确动作后才附加 CLI 指定的确认 flag；
4. 参数或目标变化后重新确认。

不要把“用户之前让我整理云盘”扩张成删除任意文件的授权。

## 未知结果

网络断开、进程超时或终端中断时，操作可能已经提交：

- 创建/发送：按幂等键、目标和时间窗查询；
- 异步导入/导出/发布：按 task/release ID 查询；
- 批量写：读取每项状态或业务数据，不整批重放；
- 审批：读取任务与实例状态，避免二次决策；
- 权限：读取成员/公开设置；
- 文件与文档：读取版本、hash、标题或目标父目录。

只有证据显示未执行，才重试。

## 验证强度

- 普通读：退出码、`ok`、查询范围和分页说明。
- 普通写：上述证据加独立业务回读。
- 高风险写：再加确认记录、恢复信息和前后差异。
- 视觉制品：API 状态之外还要打开或截图检查。
- 外部发送：核对真实受众、最终正文/附件和服务端 message/mail ID。
