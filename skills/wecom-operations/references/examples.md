# 企业微信操作｜案例与详细说明

以下案例把触发条件、处理决策和验收证据连在一起。示例中的账号、路径、对象和内容均为占位描述，执行时必须替换为用户已确认的真实范围。

## 正向案例

- **用户请求：** “把这份 Markdown 发布成企微智能文档草稿，并回读确认图片和段落。”
- **处理：** 先运行 doctor 与目标 category 的 help，预览目标、身份和写操作；获得本轮创建授权后执行，检查 `errcode == 0` 并回读文档结构。
- **验收证据：** 返回的文档标识与回读对象一致；标题、段落、图片数量可对账；没有调用消息发送，也没有暴露加密配置或内部 ID。

## 边界案例

- **场景：** 取消会议、删除待办或整体覆写文档必须先只读锁定具体对象，再获精确确认；企业不支持授权时直接停止，不绕到客户端自动化。
- **验收证据：** 未获授权的动作没有发生，结果明确标记适用范围与剩余选择。

## 失败与恢复

- **场景与处理：** 远端报错可低频重试一次；仍失败则原样保留 `help_message`、已建资源和回执，不擅自删除或重复创建。
- **验收证据：** 失败状态、已完成范围和下一次安全重试条件均可复核。
