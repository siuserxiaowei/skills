# 企业微信云端操作｜验收案例

运行依赖用户已配置的官方 `wecom-cli`。文档、待办、会议和日程分别读取对应参考页；本 Skill 不发送消息或控制客户端。

## 使用说明

- **何时使用：** 通过官方 wecom-cli 查询或管理企微文档、待办、会议和日程。
- **准备/输入：** category、可消歧对象、完整创建字段或更新 diff、时区/成员、现有配置与必要图片 helper。
- **执行方式：** doctor/help/schema 后先读基线或本地 preview，获当前写授权才 apply，按业务码和对象读回验收。
- **验收/边界：** 对象/状态/时间/内容可回读，私密回执为 `0600`；不发送消息、不读密文配置、不用客户端自动化绕过授权。

## 正向案例

### 从 Markdown 创建智能文档

- **用户请求：** “把 `/private/report.md` 创建为‘八月复盘’智能文档，并回读确认段落和图片。”
- **准备信息/输入：** 源文件归用户控制；目标 title 已确认；现有 `wecom-cli` 配置可用；若含本地图片，用户另行提供支持 `doc +doc_upload_image` 的 `WECOM_UPLOAD_HELPER`。
- **处理：** 运行 `python3 <skill-dir>/scripts/doctor.py --category doc` 并读取当前 category help/schema；先执行 `python3 <skill-dir>/scripts/create_smartpage.py --source "/private/report.md" --title "八月复盘"` 生成零写入计划；核对源、标题、图片/helper、回执目录和将创建对象，确认本轮创建授权后再添加 `--apply`；检查业务响应 `errcode == 0`，按返回对象回读结构。
- **预期输出：** 创建一个标题、段落和图片完整的智能文档；不发送消息、不暴露 secret/内部 ID。
- **验收证据：** doctor/category 结果、预览与 apply 一致、私密 `0600` 回执、返回对象与回读对象一致、段落/图片数量对账。

## 边界案例

### 图片 helper 缺失或要求顺便覆写旧文档

- **用户请求：** “图片工具没有就先建残缺版，再把旧文档整篇覆盖。”
- **边界判断：** 本地 Markdown 含图片；外部 helper 不可用；整体覆写是额外高影响动作。
- **处理：** 停止创建图片残缺对象并说明缺失前置条件；整篇替换需先只读取得准确旧对象、当前内容/版本和恢复计划，再针对精确 diff 获得确认。不能把新建授权扩展为覆盖，也不能自制未审查 helper。
- **预期输出：** 条件不足时远端无变化，旧文档保持原样。
- **验收证据：** preview 中的 missing helper、旧对象基线、未使用 `--apply` 和无 replace 请求。

## 失败与恢复

### 创建响应未知或回读无权限

- **场景：** 请求提交后连接断开，或创建返回成功但当前身份无法回读。
- **处理与恢复：** 保留本地 operation 回执和提交时间，不盲目重复创建或删除；用当前 CLI 的只读搜索/对象查询按标题、时间和返回 ID 查重。唯一对象存在则分别报告“创建成功”和“内容未能回读验证”；仍未知时保持未知状态，自动重试最多一次且仅限明确瞬时、可证明未执行的情况。
- **预期输出：** 避免重复文档，验证缺口不被伪装成完整成功。
- **验收证据：** 原响应/错误、查重范围、对象 ID（仅保存在私密回执）、回读错误、最终远端状态和下一次安全动作条件。
