# 会议与日程

## 探测可用能力

```bash
wecom-cli meeting --help
wecom-cli schedule --help
```

企业租户可能只开放其中一类。帮助输出确认不可用时，就把这一点作为结果返回，不创建测试对象。

## 创建前的最小信息

会议至少需要可读标题、开始时间、时区和时长；日程需要标题、开始及结束时间、时区。地点、说明、提醒和参与人按用户需求补充。

在写入前读取对应命令的 `--schema`，并把自然语言时间转换成该版本要求的格式。用户没有给出时区时，先依据明确上下文判断；若可能跨时区且会改变实际时间，则询问。

参与人不可凭姓名猜内部 userid。通讯录能力不可用时，应选择不邀请成员或请用户提供经确认的标识。

## 查询与更新

查询窗口保持在任务所需的最小范围。修改前先列出候选并读取详情，以标题、时间和当前状态共同锁定对象。

参与人等字段若是全量替换语义，必须把现有列表与用户要求合并后提交。不要用一个新增成员覆盖原有成员。

## 取消门

取消会议或日程属于高影响动作：

1. 只读取得精确对象；
2. 向用户复述标题、开始时间、时区及当前状态；
3. 获得针对该对象的明确确认；
4. 执行一次取消并再次查询状态。

只有标题相同或搜索结果唯一都不足以跳过确认。用户可见结果不包含 meetingid、schedule_id 或内部成员标识。
