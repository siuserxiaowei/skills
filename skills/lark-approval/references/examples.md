# Lark Approval｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “查到请假审批定义，帮我按明天上午到后天下午发起一份草稿。”
- **处理：** 固定 profile 与 user identity，先搜索并读取审批定义/schema，换算时区、校验字段和日期，再做 dry-run；只有用户确认精确内容后才发起。
- **验收证据：** 实例 ID、申请人、时间段、字段值和初始状态回读一致；未把审批通过或拒绝混同为发起。

## 边界案例

- **场景：** “把我的待办都通过”不是精确授权；逐项列出对象、风险和当前状态，必须针对具体实例获得确认。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** exit 10 或字段校验失败时回到 schema 修正计划，不换身份、不盲重试，也不绕过确认门禁。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
