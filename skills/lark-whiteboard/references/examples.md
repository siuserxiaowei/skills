# Lark Whiteboard｜验收案例

宿主 doc token、whiteboard ID、block ID 和图像 token 必须从当次文档/画板读回取得；更新格式以当前 help 为准。

## 使用说明

- **何时使用：** 查看、导出、新增或修改飞书文档中的画板结构与布局。
- **准备/输入：** 宿主文档/whiteboard、图 DSL 或节点边数据、期望变更、profile/identity 和视觉目标。
- **执行方式：** 先导出 raw nodes 与预览，校验 ID/端点/坐标，展示 diff 后更新，再同时回读结构和预览。
- **验收/边界：** 拓扑、分组、标签和可读性均通过；整体替换/清空必须有完整基线、恢复数据和精确确认。

## 正向案例

### 只新增三个流程节点

- **用户请求：** “在这块画板新增‘审核—发布—归档’三个节点并连线，不动原节点。”
- **准备信息/输入：** 用户给出宿主文档链接并指明目标画板；节点文本与方向明确；profile/identity 有编辑权限。
- **处理：** 运行 `lark-cli whiteboard --help`、`lark-cli whiteboard +query --help`、`lark-cli whiteboard +update --help`；解析 doc token 和 whiteboard ID；保存 raw nodes、边、坐标与预览；验证新增节点 ID、from/to、无环要求和无冲突位置；展示新增 diff 后写入；重新 query raw 与 preview。
- **预期输出：** 仅新增三节点两连线，原节点 ID、内容、坐标和连接保持不变，视觉上无重叠且标签可读。
- **验收证据：** 写前/写后节点与边集合 diff、原节点哈希/坐标、预览图和结构校验结果。

## 边界案例

### 新增请求夹带整体替换

- **用户请求：** “加一张流程图，旧画板碍事就清空。”
- **边界判断：** 当前 update 可能是整体替换；用户未明确授权删除原结构。
- **处理：** 先确认命令的插入/替换语义，导出 raw nodes 和预览；把新增与清空拆开。没有准确节点/边删除清单、恢复证据和显式确认时，不发送整体替换 payload。
- **预期输出：** 原画板保持不变，用户获得安全追加或另建画板方案。
- **验收证据：** 基线导出、影响 diff、确认前零写入与未调用删除/替换的记录。

## 失败与恢复

### 结构成功但视觉重叠

- **场景：** 服务端返回成功，预览中两个新节点遮挡原标签。
- **处理与恢复：** 以预览为缺陷证据；保留已创建的稳定节点 ID，只计算受影响节点的坐标修正。先 query 确认当前图，再提交最小更新并再次读取 raw/preview，不重复创建整套流程。
- **预期输出：** 重叠被修复且节点数不增加，原语义和边端点保持不变。
- **验收证据：** 修复前后截图、受影响 ID/坐标 diff、最终节点/边计数与可读性检查。
