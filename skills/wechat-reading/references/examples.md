# WeChat Reading｜使用说明与案例

## 使用说明

使用前先确定四项信息：查询的是公开书目还是个人账号数据、目标书籍或时间范围、是否需要完整分页、结果只在对话中展示还是写入指定文件。个人数据需要用户自己的 `WEREAD_API_KEY`，只能通过安全环境注入，不能出现在聊天、命令参数、日志或仓库中。

执行时先用 `python3 scripts/weread_client.py catalog` 核对当前只读端点，再选择最小必要接口。书名存在歧义时先搜索确认 `bookId`；统计书架、笔记或阅读时长时保存原始 JSON，再用 `scripts/summarize.py` 做确定性汇总。交付必须说明覆盖的端点、分页是否完成、统计口径、缺失字段和结果是否完整。

## 正向案例

**用户请求：** “用我的微信读书账号汇总 2026 年阅读时长，并列出高亮最多的五本书，结果保存为 Markdown。”

**准备信息：** 用户确认自然年度口径、允许读取个人书架/阅读统计/笔记，指定输出路径 `/absolute/path/weread-2026.md`，并已在当前进程安全提供 `WEREAD_API_KEY`。不需要导出高亮原文或其他读者信息。

**处理：** 先读取本地端点目录和 `references/api-contract.md`，分别获取阅读统计、书架与笔记数据，完成所有必要分页并保存不含密钥的原始响应。用 `python3 scripts/summarize.py reading response.json` 核对秒数转换，再按已确认书籍标识统计高亮数量；写文件前预览标题、统计口径和敏感字段清单，随后原子写入并重新打开检查。

**预期输出：** Markdown 包含总阅读时长、口径说明、五本书的书名/作者/高亮数、数据覆盖日期和缺失项；不包含 API Key、VID、好友身份、完整私人高亮或未请求的原始响应。

**验收证据：** 端点和页数可对账，汇总数与保存的 JSON 一致，五本书均由明确 `bookId` 关联，输出文件可重新读取；若服务只返回自然周期统计，报告明确说明没有伪造任意日期区间。

## 边界案例

**场景：** 用户说“帮我把《三体》加入书架并分到科幻组”，但当前官方 Gateway 只提供读取能力。

**边界判断：** 加书、移书、上传、分组、编辑笔记、点赞和评论均不在当前能力内；浏览器自动化、Cookie 抓取或逆向接口也不是这次请求自动获得的授权。

**处理：** 不调用任何写接口。可以先搜索并确认正确书籍，向用户展示书名、作者和 `bookId`，再给出在微信读书客户端中手动完成的最短步骤；只有用户另行要求研究其他实现方式时，才重新评估权限和风险。

**验收证据：** 服务调用记录中只有白名单只读端点，没有书架或分组状态变化；回复清楚区分“已找到目标书”与“尚未加入书架”，不把计划写成完成结果。

## 失败与恢复

**失败场景：** 笔记分页进行到第 4 页时收到 429，当前只拿到 86 条记录，而任务要求全年完整统计。

**处理与恢复：** 保存已完成页、最后游标、响应状态和请求时间；按客户端的有限重试策略等待，不并发轰击服务，也不更换自定义网关。仍失败时输出部分结果并标记 `partial`，说明 86 条只是下界。下一次只从已确认游标继续，完成后重新运行汇总并检查是否出现重复记录。

**验收证据：** 失败报告能说明完成到哪一页、缺少什么以及何时可安全重试；部分统计没有被写成全年总量。恢复后页数、去重键和最终记录数可对账，密钥始终未进入输出。
