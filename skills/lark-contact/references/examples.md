# Lark Contact｜案例与详细说明

命令结构按本机 `lark-cli 1.0.71` 验证。示例只返回身份解析所需字段；电话、完整组织树等信息不应顺带输出。

## 使用说明

- **何时使用：** 需要把姓名/邮箱解析为稳定用户 ID、处理同名或验证外部 ID 时读取。
- **准备/输入：** 固定租户/profile/identity，提供查询词或已知 ID、下游所需 ID 类型和最小消歧字段。
- **执行方式：** 搜索后展示候选，必要时由用户选定，再用 open ID 反查一次；不替下游自动发送或分配。
- **验收/边界：** 以租户、显示身份、状态和 canonical ID 一致性验收；组织遍历与联系方式导出不是单人解析。

## 正向案例

### 把同名人员解析为唯一 open_id

- **用户请求：** “把项目里的‘李明’解析成正确的 open_id，供后续建任务使用。他在产品部，不是外部联系人。”
- **准备信息/输入：** profile 为 `work`，当前租户和 user 身份已确认；搜索词不超过 50 字；下游只需要 `open_id`、显示名和用于消歧的最小部门信息。
- **处理：**

```bash
lark-cli whoami --profile work
lark-cli contact +search-user --profile work --as user --query '李明' --exclude-external-users --page-size 20 --format json
```

若有多个候选，展示显示名、必要的部门/企业邮箱域和 ID 后缀，请用户选择。选定后用 ID 反查一次：

```bash
lark-cli contact +search-user --profile work --as user --user-ids <open_id> --format json
```

- **预期输出：** 得到一个租户内、未停用且与“产品部”条件相符的 `open_id`。
- **验收证据：** 搜索条件、候选数、用户选择依据和反查结果一致；输出不含电话、私人邮箱或无关人员；没有自动创建任务或发送消息。

## 边界案例

### 拒绝把单人解析扩成全员通讯录导出

- **用户请求：** “把全公司的姓名、手机、邮箱都导给我。”
- **边界判断：** 单人 ID 解析不包含组织树遍历；手机和邮箱又属于额外个人信息，不能从通讯录可见性推定批量导出权限。
- **处理：** 停止在默认能力边界，说明组织遍历、敏感联系方式和批量导出需要明确用途、管理员授权与字段最小化；不尝试用 `+search-user` 分页枚举，也不切换 bot 绕过可见范围。
- **验收证据：** 没有产生组织级数据文件；记录未执行原因、所需授权和可接受的更窄方案（例如解析指定的 3 个项目成员）。

## 失败与恢复

### 搜索为空或候选仍不唯一

- **场景：** “李明”无结果，或结果很多且部门字段缺失。
- **处理与恢复：** 核对 profile/tenant、user 身份、`has_more`、是否外部用户和可见范围；向用户请求企业邮箱或更具体部门。不得从姓名猜邮箱，也不得默认取第一条。
- **验收证据：** 若补充条件后唯一命中，保留原/新查询及消歧依据；仍无法唯一确认时返回候选或缺口，不输出未经验证的 ID。候选仍超过一页时同时报告 `has_more`，外部用户状态也要保留。
