# Lark Contact｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “把项目里的‘李明’解析成正确的 open_id，供后续建任务使用。”
- **处理：** 使用固定租户和身份搜索，比较部门、邮箱等最小必要消歧信息，让用户确认唯一人选后输出 canonical ID 给下游计划。
- **验收证据：** 显示身份与 open_id 的租户一致；消歧依据可见；回复不额外泄露电话或组织信息。

## 边界案例

- **场景：** 批量导出通讯录或索取私人联系方式超出单人解析范围；按权限、用途和最小披露重新确认。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 存在同名或外部来源 ID 时不猜；保留候选并要求补充部门/邮箱，直到唯一命中。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
