# Standup Report Workflow｜案例与详细说明

以下案例以当前 lark-cli 的运行时发现结果为准；命令、schema、profile、identity 和租户都必须在执行当次重新确认。

## 正向案例

- **用户请求：** “生成今天的日程与未完成任务站会稿，上海时区，不要自动发送。”
- **处理：** 固定当天边界，读取日历 agenda 与本人任务，按唯一 ID 去重，区分已完成、逾期、今天截止和无截止，生成有来源的草稿。
- **验收证据：** 日期/时区、日程数和任务状态可对账；已完成项没有混入未完成；只返回草稿，未发群或改任务。

## 边界案例

- **场景：** “给我站会稿”不授权发送消息、更新任务状态或替负责人承诺；外部协作者信息按最小披露处理。
- **验收证据：** 任何额外写入、外部发送、权限或高风险动作均未越过用户本轮授权。

## 失败与恢复

- **场景与处理：** 某一数据源失败时标明缺失域和时间，不用另一个域推断完整工作量，也不把部分草稿称为全量。
- **验收证据：** 保留结构化错误、实际远端状态和下一步条件；没有把未知状态伪装成成功。
