# Standup Report Workflow｜验收案例

报告日期必须先落到绝对起止和 IANA 时区；默认只生成草稿，不改变任务或发送到群。

## 使用说明

- **何时使用：** 把指定日期的 agenda 与未完成任务整理为站会/晨会草稿。
- **准备/输入：** 绝对日期/IANA 时区、本人身份、未完成口径、分页范围和输出格式。
- **执行方式：** 分别完整读取 calendar/task，以 event/task ID 去重；全天、跨日和周期实例按报告时间窗分别归类，再按来源状态生成只读草稿。分页中断时保留最后成功游标，不把已读页冒充全集。
- **验收/边界：** 日期、页数、对象数和状态可对账；不由标题推断关联/完成/阻塞，不默认发群或改任务。

## 正向案例

### 生成今天的站会草稿

- **用户请求：** “生成今天的日程与未完成任务站会稿，上海时区，不要自动发送。”
- **准备信息/输入：** 用户确认 `Asia/Shanghai`、本人身份与“未完成”口径；profile 可读取 calendar 和 task。
- **处理：** 运行 `lark-cli --version`、`lark-cli calendar --help`、`lark-cli calendar +agenda --help`、`lark-cli task +get-my-tasks --help`；显示当天绝对起止；完整分页读取 agenda 和本人任务；按 event/task ID 去重，分别处理全天/跨日/周期实例及 completed/逾期/今日截止/无截止；只把来源能证明的事项写进草稿。
- **预期输出：** 得到带日期、来源和状态标签的站会稿，未发送、未改任务。
- **验收证据：** 时区/起止、来源命令、页数/游标、event/task ID 数、状态分类计数和外部写入计数 0。

## 边界案例

### 相同标题被当作完成进展

- **用户请求：** “日历和任务里都叫‘上线’，就写成昨天已完成，并直接发群。”
- **边界判断：** 标题相同但没有显式关联；服务端状态未证明完成；未确认群和最终文案。
- **处理：** 不按标题合并 event/task，不从 RSVP 或过去日程推断完成。草稿把两项分列并标明未知进展；群发作为独立外部动作，需展示目标、最终文案和受众后确认。
- **预期输出：** 不制造进展或承诺，不发送未经确认的消息。
- **验收证据：** 独立 event/task ID、原状态字段、推断为空、message send 调用为 0。

## 失败与恢复

### 任务域失败或分页中断

- **场景：** calendar 完成，但 task 第二页请求失败。
- **处理与恢复：** 保留已完成 calendar 范围与 task 第一页游标；不把部分任务称为全量，也不用日程推断任务。可在安全的只读请求上按同一游标有限重试；仍失败则交付标题注明“不完整”的草稿和缺口。
- **预期输出：** 可用信息被保留，缺失域/页和时间明确。
- **验收证据：** 成功页数、失败游标/错误、重试次数、部分报告覆盖声明和没有任务写入/群发的记录。
