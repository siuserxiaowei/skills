## 跨来源初步洞察（不等于最终结论）

1. **Pi 的可学习性来自“层次少且可回源”，不等于功能少。** 官方材料稳定地把系统拆成 `pi-ai → pi-agent-core → pi-coding-agent/pi-tui`，社区则围绕权限、MCP、网页、context pruning、多 Agent、GUI、telemetry 补出完整产品面。
2. **Pi 与 DeepSeek Harness 的主差异不是“有没有插件”，而是插件化的边界。** Pi 保留小而明确的核心 runtime，以 TypeScript extensions 叠加产品能力；DSH 用 Cordis 把 model、loop、session、sandbox、storage、scheduler、UI 也变成可替换插件，组合自由度更高，但需要学习更大的生命周期/依赖图。
3. **会话语义值得单独成章。** Pi 强调 JSONL tree、回退/分叉与 compaction；DSH 强调 append-only event stream、trajectory、resume/fork/search/replay。两者都拒绝纯线性聊天记录，但数据模型与 runtime ownership 不同。
4. **“结束”不是一个布尔值。** DEV 的 background-agent 案例直接暴露 `agent_settled` 与“所有派生异步工作都完成”的差异；这正好可以用来设计学习站的停止条件、follow-up queue 与 transitive completion 单元。
5. **商业化最密集的方向不是再造 Agent Loop，而是壳层与治理。** GitHub/npm 高信号项目集中在 Web/desktop UI、protocol adapters、permissions/sandbox、multi-agent coordination、memory/context、observability、remote access 与 vertical workflows。
6. **安全是 Pi 默认哲学最需要显式教学的反面。** 作者原文把 Pi 形容为 YOLO by default；社区权限插件、sandbox、web SSRF 防护与 arXiv SHarD 论文共同表明，生产使用必须把权限、网络、技能供应链与可审计结果作为第一等设计。
7. **固定模型、替换 harness 的对比比泛泛“谁更聪明”更有教学价值。** Substack code-review、HN local benchmark、YouTube Pi-vs-OpenCode 都采用这一思路；但多数样本小、配置不完全等价，最终知识库应把实验设计与 caveat 放在结果数字之前。
